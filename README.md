# Student Attendance Management System

A complete Django attendance application for administrators, teachers, and students. It provides:

- Student and teacher management
- Seven-subject teacher assignment
- Present/Absent attendance tracking
- Duplicate attendance protection
- Role-based access control
- Django Admin search, filtering, import, and export
- CSV and Excel support through `django-import-export`
- Admin and teacher dashboards
- JWT-authenticated REST APIs
- SQLite database support for local development
- Responsive themed web pages

## 2. Requirements

- Windows, macOS, or Linux
- Python 3.12 or newer
- Internet access for installing packages
- SQLite is used for local development

Check your Python version:

```powershell
python --version
```

## 3. Install Locally on Windows

Open PowerShell in the project directory:

```powershell
cd D:\attendness_management_system
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell blocks activation, run this once in an administrator PowerShell or use the interpreter directly:

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

The current dependency file may have been generated with `pip freeze`, so it can include transitive packages such as `asgiref`, `tablib`, and `tzdata`. This is expected.

## 4. Initialize the Database

Apply every migration:

```powershell
.\venv\Scripts\python.exe manage.py migrate
```

Run the project checks:

```powershell
.\venv\Scripts\python.exe manage.py check
```

Create the administrator account:

```powershell
.\venv\Scripts\python.exe manage.py createsuperuser
```

Enter a username, email address, and password when prompted. The password is stored by Django as a secure hash.

## 5. Load Sample Data

Create the seven default subjects and seven teacher accounts:

```powershell
.\venv\Scripts\python.exe manage.py seed_teachers
```

This command is safe to run again. It creates or updates these subjects:

```text
IPS1, FMI1, ITC, PPWC, DPOS, CN, MLC1
```

It also creates teacher profiles with employee IDs `TCH-001` through `TCH-007` and writes the generated credentials to `teachers.csv`.

Load the included 60-student sample file:

```powershell
.\venv\Scripts\python.exe manage.py load_students
```

Use a different CSV file with:

```powershell
.\venv\Scripts\python.exe manage.py load_students --file path\to\students.csv
```

Supported student CSV columns:

```text
name,regd_no,class_name,roll_no,email
```

The loader also accepts the legacy column names `Name`, `Regd_No`, `Class`, `roll_No`, and `Email`.

Registration number and email must be unique. Roll numbers may repeat in different classes.

## 8. How Students Log In

Students currently use their registration number and exact registered name. They do not use a password in the current design.

Example:

```text
Registration number: REG001
Name: Aarav Sharma
```

The name must match the database value, ignoring upper/lowercase but not spelling. The student then sees attendance summaries by subject.

Student passwords are intentionally not stored in the student CSV. If password-based student authentication is required later, add a Django user relationship or a separate student authentication model and never store plain-text passwords in CSV files.

## 9. How Teachers Log In

Teachers use Django Authentication with a username and password. After running `seed_teachers`, open `teachers.csv` to see the generated credentials.

The seeded passwords are employee IDs, for example:

```text
Username: harsh
Password: TCH-001
Subject: IPS1
```

Teacher accounts should change these initial passwords before sharing the project. The `teachers.csv` file contains plain-text credentials and must not be committed to a public repository.

## 10. Attendance Workflow

1. Log in as a teacher.
2. Open the teacher dashboard.
3. Select an assigned subject.
4. Choose the attendance date.
5. Set each student to `Present` or `Absent`.
6. Save attendance.
7. The dashboard displays record totals and the Present percentage.

The database prevents duplicate records for the same student, subject, and date. Teachers can edit only records they created. Administrators can edit any attendance record.

## 11. Data Model

### Student

- `name`
- `regd_no`, unique
- `class_name`
- `roll_no`
- `email`, unique

### TeacherProfile

Links a Django `User` to a unique `employee_id`.

### Subject

- Unique subject `code`
- Subject `name`
- Multiple assigned teachers through `teachers`
- A legacy `teacher` field is retained for compatibility with older records

### AttendanceRecord

- `student`
- `teacher`, the user who created the record
- `subject`
- `date`
- `status`: `present` or `absent`
- Unique combination of `student`, `subject`, and `date`

## 12. Django Admin

Open:

```text
http://127.0.0.1:8000/secure-admin/
```

Log in with the superuser created by `createsuperuser`.

Admin features include:

- Add, edit, delete, and view students
- Search students by registration number, name, class, roll number, or email
- Filter students by class
- Manage teacher users and employee profiles
- Assign one or more subjects to teachers
- Manage subjects
- Manage attendance records
- Search attendance by student, teacher, and subject
- Filter attendance by class, subject, teacher, date, and status
- Import and export supported models as CSV or Excel-compatible files

To import students:

1. Open Django Admin.
2. Select `Students`.
3. Click `Import`.
4. Select a CSV or XLSX file.
5. Confirm the preview.
6. Run the import.

## 13. Role-Based Access

### Administrator

A Django superuser has full access to users, teachers, profiles, students, subjects, attendance, imports, exports, and dashboards.

### Teacher

A teacher account is an active Django user with `is_staff=True` and a `TeacherProfile`. Teachers can:

- Log in through the teacher page
- View assigned subjects
- Mark attendance
- Edit attendance records they created
- View their own attendance-related records

Teachers cannot manage students, teachers, subjects, or attendance belonging to another teacher.

## 14. REST API and JWT Authentication

### Obtain a JWT access token

Send a POST request to:

```text
POST /api/token/
```

JSON body:

```json
{
	"username": "harsh",
	"password": "TCH-001"
}
```

The response contains `access` and `refresh` tokens.

Use the access token on API requests:

```text
Authorization: Bearer <access-token>
```

Refresh an expired access token:

```text
POST /api/token/refresh/
```

```json
{
	"refresh": "<refresh-token>"
}
```

### API resources

| Resource | Endpoint | Purpose |
| --- | --- | --- |
| Students | `/api/students/` | List and administer students |
| Teachers | `/api/teachers/` | View active staff teachers |
| Subjects | `/api/subjects/` | List or administer subjects |
| Attendance | `/api/attendance/` | Create and manage attendance |

Student and subject writes require an administrator. Attendance creation assigns the authenticated teacher automatically. Attendance updates are restricted to the record creator unless the requester is an administrator.

Example attendance JSON:

```json
{
	"student": 1,
	"subject": 3,
	"date": "2026-09-15",
	"status": "present"
}
```

## 15. Local Database Configuration

SQLite is the default when `DB_ENGINE` is not set. The database file is:

```text
db.sqlite3
```

SQLite data persists across server restarts. Back up `db.sqlite3` regularly if it contains important local data.

## 16. Troubleshooting

### `No module named django`

Activate the virtual environment or call its Python directly:

```powershell
.\venv\Scripts\Activate.ps1
python manage.py runserver
```

### CSRF verification failed

Refresh the login page with `CTRL+F5`. Login pages are configured not to cache CSRF tokens. Also confirm that the browser is accepting cookies and that the URL matches `ALLOWED_HOSTS` and `CSRF_TRUSTED_ORIGINS`.

### Student login fails

Use the exact registration number and registered name from the database. For example, `REG001` belongs to `Aarav Sharma`, not `Aarav Sharm`.

### Migrations are pending

Run:

```powershell
python manage.py makemigrations
python manage.py migrate
```

### Seed data fails

Confirm that migrations have been applied first:

```powershell
python manage.py migrate
python manage.py seed_teachers
```
